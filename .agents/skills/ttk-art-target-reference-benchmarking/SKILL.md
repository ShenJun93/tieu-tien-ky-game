# ttk-art-target-reference-benchmarking

## WHEN TO USE

Starting or reviewing art direction for characters, enemies, environment, UI, VFX, animation presentation, or a vertical slice whose visual quality target is otherwise subjective or undefined.

## PRODUCT QUESTION

What observable quality bar should this slice reach, and can the team explain the target without copying another game's protected expression?

## MUST

- Establish a small reference set before expensive implementation: internal targets plus external references chosen for specific qualities such as silhouette clarity, material hierarchy, value grouping, UI density, impact readability or mobile legibility.
- Extract principles, not assets: record **why** a reference works and translate that into TTK-specific criteria.
- Define a target and a rejection bar. “Better than current” is insufficient when current is known prototype quality.
- Keep cute/chibi × spectacular cultivation power and Readable Chaos as TTK identity constraints unless canon is explicitly reopened.
- Apply asset provenance/intake rules to any external material entering the repository.

## MUST NOT

- Copy distinctive characters, maps, UI compositions, icons, animation, lore, audio or other protected expression.
- Use moodboards as proof that implementation reached the target.
- Select references only after implementation to rationalize existing output.
- Chase screenshot beauty while ignoring in-motion mobile readability.

## EXIT CONDITION

The active slice has explicit observable visual criteria that can be compared against the running artifact. Human judgment determines whether the result BELONGS; reference similarity itself is never the acceptance metric.
